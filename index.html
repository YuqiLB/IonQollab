BEHIND THE SCENE

What actually ran?

No quantum job.

Classical mathematics. Your text becomes UTF-8 bytes, each stored as fixed-width base-N digits. Each digit is encrypted with tiny, unpadded textbook RSA. After a verified period yields factors, the recovered exponent decrypts the actual packet.

Quantum execution. Illustrative mode uses labeled deterministic sample measurements. Live mode runs the bounded Shor order-finding circuit on your Qollab-selected simulator. Only public N and the order-finding base are sent; the chosen primes stay in the game. A failed live job never becomes sample success. The wave animation illustrates interference; it is not a backend circuit trace.

Post-quantum exchange. The ML-KEM, key derivation, and authenticated-encryption sequence is an illustration. No actual ML-KEM or authenticated encryption runs here. Both messages stay in this browser’s memory; there is no secure chat service.

This is a deliberately insecure RSA teaching example: the public modulus is capped at N ≤ 63, there is no production padding, and classical factoring is trivial at this size. For p = 3, q = 5, e = d = 3, so even the public exponent decrypts. Shor's order-finding lesson illustrates the recovery chain; it does not demonstrate breaking modern RSA. ML-KEM is designed to resist known quantum attacks; it is not a claim of invulnerability. Public keys must also be authenticated in a real protocol.

Homomorphic encryption means computation on encrypted data; it is a different concept from post-quantum cryptography.
